§ I
manifesto

Agentes rápidos ainda precisam de processos confiáveis.

Velocidade sem método é ruído. O FlowAI é uma biblioteca de princípios operacionais que se manifestam como etapas, agentes e registros — para que autonomia não vire abandono.

  1. 01°

    Entender antes de editar.

    Toda solicitação é classificada por intenção, escopo e contexto antes de qualquer linha ser tocada.

  2. 02°

    Planejar antes de implementar.

    Um plano explícito substitui adivinhações. Etapas, arquivos afetados e riscos são nomeados antes da execução.

  3. 03°

    Preservar o trabalho existente.

    O código que já funciona é patrimônio. Mudanças propõem-se sobre o que existe, nunca contra.

  4. 04°

    Validar antes de declarar sucesso.

    Nenhuma tarefa é concluída sem evidência. Testes, compilação e critérios objetivos sustentam cada conclusão.

  5. 05°

    Registrar conhecimento durável.

    Decisões, contextos e aprendizados são escritos em memória de projeto — acessíveis às próximas execuções.

  6. 06°

    Pedir autorização antes de ações sensíveis.

    Operações irreversíveis passam por um portão. Autonomia não significa licença para agir sem consentimento.

§ II
workflow · trilha narrativa

Seis estágios, uma trilha contínua.

Cada solicitação entra como intenção e sai como registro. O que está entre os dois é o trabalho silencioso de classificar, planejar, implementar, validar e lembrar.

01° entry · solicitação

Solicitação

A intenção humana entra no sistema como texto, contexto e restrições. Nada é executado ainda — apenas recebido e armazenado com fidelidade.

// input
request → { intent, scope, context }
triage · classificação 02°

Classificação

O Nexus examina a solicitação e a classifica: tipo de tarefa, domínio, complexidade, arquivos provavelmente envolvidos, riscos antecipados.

// classify
type: refactor · risk: low
03° plan · planejamento

Planejamento

O Scout mapeia o território: arquivos a tocar, arquivos a preservar, ordem de operações, critérios de conclusão. Um plano vira objeto verificável.

// plan
steps: [edit, test, verify, document]
build · implementação 04°

Implementação

O Forge executa o plano em passos controlados. Cada alteração é small, revisável e reversível. Nada é feito em lote cego.

// build
patch → file.ts · status: applied
05° verify · validação

Validação

O Aegis submete o trabalho a critérios objetivos: testes, tipos, compilação, lint, contratos. Sem verde, não há sucesso — há hipótese.

// verify
tests: 24/24 · types: clean
durable · memória 06°

Memória

O Patch escreve o que foi aprendido: decisões tomadas, contextos preservados, atalhos descobertos. O projeto fica mais inteligente a cada ciclo.

// remember
memory → AGENTS.md · status: persisted
§ III
sistema de agentes

Seis especialistas, um mesmo sistema.

Cada agente tem papel definido, símbolo próprio e jurisdição clara. Eles se conectam por contratos explícitos — não por improvisos de prompt.

classificador

Nexus

Recebe a solicitação e a decompõe em tipo, escopo, risco e contexto. É a porta de entrada — onde a intenção vira estrutura.

° etapa 02 · classificação
planejador

Scout

Explora o código, mapeia dependências e propõe um plano. Sua função é ver antes — antecipar o caminho.

° etapa 03 · planejamento
portão

Gate

Avalia riscos e pede autorização antes de ações sensíveis.

° autorização
construtor

Forge

Executa o plano em passos controlados e reversíveis.

° etapa 04 · implementação
validador

Aegis

Submete o trabalho a critérios objetivos — testes, tipos, contratos. Sem evidência, não há conclusão.

° etapa 05 · validação
memória

Patch

Escreve decisões, contextos e aprendizados em memória durável. Costura o que foi feito ao que será feito — o projeto lembra de si mesmo.

° etapa 06 · memória · persistente
6 agentes · 6 papéis · 1 sistema
§ IV
duas distribuições · mesma oficina

§ V
instalação · terminal

Três linhas para começar.

Instale. Inicialize. Chame o FlowAI dentro do seu agente. O workflow passa a operar entre a solicitação e a resposta.

flowai — bash — 80×24
~ / project
$ npm install @mvoikolesco/flowai
° adicionado a dependencies · 1 pacote · 12s
$ npx flowai init
° AGENTS.md criado · skills registradas · memória inicializada
$ flowai run "adicionar validação no endpoint /auth"
° Nexus classificou · Scout planejou · Forge implementou
° Aegis validou · Patch persistiu memória
° workflow concluído · 6 etapas · evidências em /memory
